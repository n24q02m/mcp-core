## 2025-02-28 - Dynamic Form Errors and Accessibility
**Learning:** When dynamically injecting form elements and handling client-side validation (like a multi-step OTP input), simply displaying an error message visually is not enough. Screen readers need `aria-errormessage` explicitly linking the invalid input to the error container ID when an error occurs, and `aria-invalid="true"`. Furthermore, when the error state is cleared (e.g. on subsequent `input` events), the `aria-errormessage` attribute *must* be removed along with `aria-invalid`, otherwise screen readers may permanently announce the field as invalid. Finally, explicitly calling `.focus()` on the invalid input is critical for both keyboard navigation users and screen reader users to be immediately aware of where the correction needs to happen.
**Action:** Always ensure that dynamically rendered forms clear both `aria-invalid` and `aria-errormessage` upon retry/input, and explicitly call `.focus()` on the invalid element when blocking submission.

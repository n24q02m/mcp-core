## 2025-03-26 - Command Injection Vulnerability via PowerShell String Interpolation
**Vulnerability:** PowerShell executed URLs via string interpolation and `-EncodedCommand` which introduces an arbitrary command execution risk if the encoding requirements change, or through specific environment constraints. Although currently using Base64 encoding provides some safety, strictly passing string interpolations into a script block execution introduces risk.
**Learning:** Even when Base64 encoding user data before interpolation into shell scripts, using the shell string itself to map variables inside a script is risky. The `openInPowerShell` and `_open_in_powershell` functions originally interpolated the base64 URL directly into the command string (`$url = ...FromBase64String('{base64Url}')`).
**Prevention:** Always use parameterized execution for script arguments rather than string interpolation. In PowerShell, this means using `-Command` and passing the user input as a separate process argument which is safely consumed via `$args[0]` within the script block (`& { $url = [System.Text.Encoding]::UTF8.GetString([System.Convert]::FromBase64String($args[0])); Start-Process $url } base64_url`).

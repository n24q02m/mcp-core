## 2025-05-15 - [Node.js `crypto.timingSafeEqual` Variable-Length Secret Leak]
**Vulnerability:** The standard `crypto.timingSafeEqual` throws an error if buffer lengths do not match. To prevent this, code frequently included an early return (`if (ab.length !== bb.length) return false`), which leaks the expected length of the secret (e.g. passwords) via an observable timing difference.
**Learning:** Checking for equality in length and returning early creates a timing attack vulnerability for variable-length secrets (like passwords), which allows an attacker to guess the correct password length. Because `crypto.timingSafeEqual` mandates equal buffer lengths, handling different length buffers safely in Node.js requires a specific pattern.
**Prevention:** Instead of early returns on length mismatch, compute `isLengthEqual`, and conditionally select the target buffer to compare against (i.e. `target = isLengthEqual ? ab : bb`) before calling `crypto.timingSafeEqual(target, bb)`. Return `isLengthEqual && isMatch`. This guarantees the function executes in constant time relative to the provided secret's length without failing on variable length inputs.
